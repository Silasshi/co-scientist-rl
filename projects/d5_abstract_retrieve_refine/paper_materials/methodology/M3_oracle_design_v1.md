# Oracle Abstraction Design v1 — D5 Realignment

*Finalized 2026-04-25 based on REVIEWER_STANDARDS_v1.md + user decisions. Status: LOCKED for Phase 2 build.*

## User-locked decisions (2026-04-25)

- **Categories**: 6 (Insights / Methodology / Theory / Math / Empirical / Failure-modes) ✓
- **Generated by**: Opus 4.7 (ceiling estimate; will compare to Qwen3-30B-generated oracle in Phase 1+ as realistic estimate)
- **Citation format**: hybrid — full bibliographic on first occurrence (Author et al. YEAR. "Title" arxiv:XXXX), minimal `(Author YEAR)` thereafter
- **Granularity**: 0-3 items per category per paper (most papers contribute to only 2-3 categories)
- **Paper coverage**: all ~30-60 bibliography papers; Opus filters per-paper irrelevance (zero items OK if not relevant)
- **Content depth**: title + abstract + S2 TLDR for all papers; full-text fetch for top 5 most-central papers (centrality determined by S2 citation count or manual curation)
- **Multi-round structure**: 3 rounds with cumulative memory across rounds

## Goal

Design the structure of the "oracle abstraction" file — what would D5's pipeline produce if Qwen3-30B perfectly executed the multi-round retrieve-extract-aggregate process across the source paper's bibliography. This file is the upper-bound estimator: if we feed this into σ (frozen 30B + oracle) or μ (trained 30B + oracle), the resulting plan quality is the ceiling for the D5 architecture.

## Design principles (from REVIEWER_STANDARDS_v1.md)

1. **Oracle content categories should map onto reviewer-focus areas** — so that a final plan grounded in oracle content automatically addresses reviewer-non-negotiables.
2. **Real bibliography references with citations** — reviewers penalize hallucinated/missing citations (Source 1-4 of Part A); plan grounding requires real refs.
3. **Multi-round extraction with cumulative memory** — simulates the iterative pipeline (per Phase 2+ plan).
4. **Per-paper attribution** — every extracted item should cite its source paper.
5. **Avoid anti-patterns**: no "Pattern N" structural scaffolds without mechanism; no generic algorithm names without instantiation; no placeholder equations.

## Proposed oracle structure

### File-level structure

```
# Oracle Abstraction for D5 — TTT-Discover Goal (multi-round simulated)

## Metadata
- Bibliography source: TTT-Discover (arxiv 2601.16175) backward citations via S2 API
- Number of papers extracted: N (~30-60 from bibliography)
- Number of extraction rounds: K (~3-5)
- Generated by: Opus 4.7 simulating Qwen3-30B's pipeline (placeholder oracle)
- Generated date: YYYY-MM-DD

## Section 1 — Insights
[Items, each citing source paper]

## Section 2 — Methodology
[Items, each citing source paper]

## Section 3 — Theoretical framing
[Items, each citing source paper]

## Section 4 — Math / Formalism
[Items, each citing source paper]

## Section 5 — Empirical setup
[Items, each citing source paper]

## Section 6 — Failure modes / Limitations from prior work
[Items, each citing source paper]
```

### Six categories (mapped to reviewer-focus dimensions)

| Category | Maps to reviewer focus | What goes here |
|---|---|---|
| **1. Insights** | Originality, Significance, Problem framing | High-level conceptual moves: "Test-time training only works if X"; "Self-improvement saturates because Y"; "AlphaZero's MCTS works because Z". 1-3 sentences each, citing the paper that observed this. Used by plan-gen to frame the problem. |
| **2. Methodology** | Soundness, Reduction-to-primitives | Concrete mechanisms reusable in this plan: "MCTS with PUCT selection (Silver et al. 2017, AlphaZero)"; "REST-style self-distillation loop (Singh et al. 2024)". Each item names the mechanism + cites paper + states what's specifically reusable. |
| **3. Theoretical framing** | Originality, theoretical hook, Soundness | Algorithm reductions and theoretical guarantees: "MCTS as variational inference (Wang et al.)"; "Self-distillation as policy improvement (Anthony 2017)". Connects this work to known primitives. |
| **4. Math / Formalism** | Soundness, claim support | Specific objective functions, gradient forms, update rules with full RHS. "REINFORCE gradient: ∇J = E[R · ∇log π] (Williams 1992)"; "Entropy-regularized objective: J_β = E[R - β · H(π)] (Williams 2017)". Used by plan-gen to write proper formal sections. |
| **5. Empirical setup** | Reproducibility, statistical rigor, Significance | Concrete benchmarks, baselines, prior numbers, eval protocols. "Erdős minimum-overlap problem: prior best 0.380924 (paper Y, year)"; "AtCoder Heuristic Contest 39: top human 566,997 (paper Z)". Used by plan-gen to write specific Empirical sections with cited numbers. |
| **6. Failure modes / Limitations** | Originality (gap analysis), reward-hacking analysis, Significance | What prior work didn't solve, with attribution: "Prior self-training methods saturate after few iterations (Singh 2024)"; "MCTS for math is brittle to reward noise (paper X)"; "Frozen-LLM search hits ceiling at scale (paper Y)". Used by plan-gen for Hypothesis (motivation) and Limitations sections. |

### Per-item format

Each item in any section follows:

```
### [Item N]: <One-sentence summary>
- **Source**: Author1, Author2 et al. YEAR. "<Paper title>" arxiv:XXXX
- **Content**: <2-4 sentence elaboration with concrete details — formulas/numbers/specifics>
- **Applicability to TTT-Discover goal**: <1-2 sentences on how this is reusable>
```

Example (from Insights):

```
### Insight 3: Self-improvement loops saturate after 3-5 iterations on small models
- **Source**: Singh et al. 2024. "Beyond Human Data: Scaling Self-Training for Problem-Solving with LLMs" arxiv:2312.06585
- **Content**: ReST-EM showed monotonic gains for ~3 iterations, then plateau. Reward-model overfitting and policy-distribution narrowing identified as failure modes. Open: whether plateau scales with model size.
- **Applicability**: Use as Limitations / Hypothesis grounding — TTT-Discover should characterize its own saturation curve and explain why test-time-RL avoids the plateau (per-problem reset).
```

### Multi-round simulation logic

**Round 1** (cold start):
- Per paper in bibliography: Opus reads (title + abstract + maybe S2 TLDR)
- Extracts 0-3 items per category for that paper
- No cumulative memory, just per-paper extraction

**Rounds 2 to K** (refinement):
- Per paper: Opus sees prior round's accumulated abstraction + current paper
- Refines: "is this paper's contribution already covered? If yes, do I update the existing item with more nuance? If no, add new item."
- Result: cumulative abstraction grows but with deduplication and increasing precision

**Final state** (after K rounds): the oracle file. Each item has been seen (or considered) by Opus K times in the context of all bibliography papers.

K = 3-5 rounds is reasonable. Ablation on K is a future test.

## Implementation plan (Phase 2)

After Phase 1C (archive + protocol setup) completes, Phase 2 will:

1. **Phase 0b — bibliography fetch**: extend `src/co_scientist/shared/paper_retrieval.py` with `fetch_paper_bibliography(arxiv_id)` via S2 API (`/paper/arxiv:{id}/references?fields=title,authors,year,abstract,tldr,externalIds`). Fetch TTT-Discover (arxiv 2601.16175) backward refs. Store as `projects/d5_abstract_retrieve_refine/data/bibliography/resolved_v1.jsonl`.
2. **Identify top-5 central papers** for full-text fetch: highest in-citation count among the bibliography (proxy for centrality), or hand-curate if obvious (likely AlphaZero, AlphaEvolve, ReST, Voyager, MCTS classic).
3. **Multi-round Opus extraction script**: `src/co_scientist/d5_abstract_retrieve_refine/build_oracle_v2.py`:
   - Round 1 (cold): per paper, Opus subagent extracts 0-3 items per category from title+abstract+TLDR (or full text for top 5)
   - Rounds 2-3 (refine): Opus sees prior round's accumulated state + paper, refines with deduplication
   - Output: `projects/d5_abstract_retrieve_refine/data/oracles/oracle_v2_2026_04_26_build/final.md` (replaces `smoke_v3_oracle_abstraction.md` for new runs)
4. **Audit**: spot-check the resulting oracle for citation accuracy (random 5 items, verify cited papers exist on S2 + relevant content matches)
